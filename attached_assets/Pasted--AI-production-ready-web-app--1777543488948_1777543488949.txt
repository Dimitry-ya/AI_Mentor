# КОНТЕКСТ ПРОДУКТА

AI-Ментор — внутренний продукт для создания, редактирования, публикации и прохождения обучающих единиц.

Продукт состоит из зон:

1. Каталог обучения
2. Конструктор обучения
3. Предпросмотр / песочница
4. Прохождение обучения сотрудником
5. Аналитика
6. Админ-панель / управление доступом

Основная UX-модель:

Duolingo × Notion × AI Copilot

Duolingo:
- ведёт пользователя по шагам;
- показывает прогресс;
- подсказывает следующий шаг;
- снижает когнитивную нагрузку;
- не заставляет пользователя искать, куда идти дальше.

Notion:
- гибкий редактор блоков;
- чистый рабочий canvas;
- структура слева;
- контекстные действия;
- редактирование без ощущения тяжёлой админки.

AI Copilot:
- помогает создавать контент;
- предлагает улучшения;
- проверяет ошибки;
- работает inline, внутри сценария, а не как отдельная вкладка.

Главный принцип:
не “пользователь сам строит обучение”, а “система ведёт пользователя к готовому обучению”.

- Если опубликовано и изменено: “Есть изменения”.

# SCENARIO FOOTER ДЛЯ BUILDER

В каждом редактируемом блоке должен быть sticky bottom action bar внутри центральной рабочей области.

Для экранов:
- Онбординг

- Практический блок
- Раздел
- Кейс
- Вопрос

Добавить нижнюю панель действий.

Слева:
- “Назад”
- “Отмена”

Справа:
- “Сохранить”
- “Далее”

Логика:
- “Назад” переводит к предыдущему логическому элементу структуры.
- “Далее” переводит к следующему логическому элементу структуры.
- “Сохранить” сохраняет текущий блок и показывает toast “Изменения сохранены”.
- “Отмена” возвращает пользователя к предыдущему состоянию выбранного блока, если есть несохранённые изменения.

Если автосохранение уже сработало, при “Отмена” показывать confirm modal:
- Заголовок: “Отменить последние изменения?”
- Кнопки: “Остаться” / “Отменить изменения”

Если следующий элемент не создан:
- кнопка должна называться “Создать следующий шаг”.

Если текущий блок последний:
- вместо “Далее” показывать “Проверить обучение”.

Если проверка пройдена:
- вместо “Проверить обучение” показывать “Опубликовать”.

Если в текущем блоке есть критические ошибки, “Далее” доступна, но перед переходом показывать предупреждение:
- Заголовок: “В этом блоке остались ошибки”
- Текст: “Можно перейти дальше и вернуться к ним позже.”
- Кнопки: “Остаться” / “Перейти дальше”

Пример последовательности для тренажёра:
Онбординг → Теоретический блок → Теория 1 → Практический блок → Раздел 1 → Кейс 1 → Вопрос 1 → Завершение.

Для экзамена:
Онбординг → Практический блок → Раздел 1 → Кейс 1 → Вопрос 1 → Завершение.

Важно:
- пользователь не должен вручную искать следующий блок в дереве;
- система должна вести пользователя по структуре;
- это основа UX-модели Duolingo × Notion.

- “Заполните заголовок, чтобы сотрудник понял, с чего начинается обучение”
- “Выберите рубрику A-Book, чтобы AI использовал проверенную базу знаний”
- “Пока нельзя опубликовать: осталось исправить 3 пункта”
- “Готово, изменения сохранены”
- “Этот блок защищён: он нужен для корректного прохождения обучения”
- “Введите ответ, чтобы отправить его на проверку”
- “Вы на шаге 2 из 3”
- “Можно перейти дальше и вернуться к ошибкам позже”

# КЛЮЧЕВЫЕ UX-ТРЕБОВАНИЯ

1. Не оставлять пустой центр экрана.
2. Всегда показывать следующий лучший шаг.
3. Всегда показывать готовность обучения.
4. Настройки должны быть контекстными.
5. AI должен быть встроен inline.
6. Ошибки должны быть видны до публикации.
7. Builder должен вести пользователя, а не просто давать поля.
8. Прохождение обучения должно быть линейным и простым.
9. Админские сценарии должны быть мощными, но не шумными.
10. Прогресс в preview / learner flow должен быть заметным.
11. У пользователя всегда должны быть понятные действия:
    - Назад
    - Отмена
    - Сохранить
    - Далее
12. Продукт должен выглядеть как реальный production-ready enterprise tool.

# LAYOUT QA CHECKLIST

Перед завершением работы обязательно пройти весь интерфейс и проверить:

1. Нет ли пустых белых карточек без смысла.
2. Не обрезаются ли иконки.
3. Все ли карточки в одном ряду одинаковой высоты.
4. Все ли изображения 16:9.
5. Нет ли случайных отступов больше 40px между связанными блоками.
6. Не прилипают ли элементы к краям экрана.
7. Есть ли sticky footer там, где пользователь заполняет форму.
8. Есть ли кнопки “Назад”, “Отмена”, “Сохранить”, “Далее”.
9. Есть ли понятный next action на каждом экране.
10. Не появляется ли горизонтальный скролл.
11. Работает ли интерфейс на ширине 1440px и 1920px.
12. Не ломается ли таблица доступов.
13. Не ломается ли root overview.
14. Не теряется ли пользователь при переходе между блоками.
15. Все тексты на русском языке.
16. Прогресс в предпросмотре и прохождении заметен без поиска глазами.
17. Primary CTA один на экран.
18. Красный цвет не используется как декоративный шум.
19. Empty states объясняют, что делать дальше.
20. Все модальные окна имеют понятные действия.

Если пункт не выполняется — исправить до финального результата.
