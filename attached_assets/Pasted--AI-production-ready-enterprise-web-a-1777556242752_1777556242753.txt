# ГЛАВНАЯ ЦЕЛЬ

Сейчас интерфейс местами выглядит как кастомный прототип: неправильные цвета input / textarea / select, лишние иконки в stepper, странная нижняя панель, лишняя кнопка “Отмена”, статус “Готово к публикации” расположен не там, часть форм выглядит не по дизайн-системе.

Нужно привести продукт к виду реального внутреннего банковского инструмента.

AI-Ментор должен ощущаться как:

Duolingo × Notion × AI Copilot × Core DS

Duolingo:
- ведёт пользователя по шагам;
- показывает прогресс;
- снижает когнитивную нагрузку;
- не заставляет искать следующий шаг вручную.

Notion:
- структура слева;
- рабочая область по центру;
- контекстная панель справа;
- гибкое редактирование блоков.

AI Copilot:
- помогает создавать и проверять контент;
- работает inline;
- использует A-Book как часть сценария.

Core DS:
- банковский визуальный язык;
- системные input / select / textarea / button;
- аккуратные состояния;
- строгая типографика;
- минимум декоративного шума.

# CORE DS / ДИЗАЙН-СИСТЕМА БАНКА

Перед визуальной доработкой изучи Core DS.

Если можно подключить библиотеку напрямую — используй компоненты из Core DS.

Если прямое подключение невозможно:
- визуально и структурно воспроизведи Core DS-подход через текущие компоненты проекта;
- не стилизуй элементы “на глаз”;
- все input, textarea, select, dropdown, checkbox, radio, button, modal, tooltip, table, stepper должны выглядеть в духе Core DS.

Обязательное правило:
все формы должны выглядеть как банковские системные формы, а не как кастомные серые поля из прототипа.

# ИСПРАВИТЬ INPUT / TEXTAREA / SELECT

Сейчас поля выглядят неправильно: серые фоны, случайные бордеры, тени и focus-state не похожи на Core DS.

Привести к Core DS-like стилю все:
- input;
- textarea;
- select;
- dropdown;
- search;
- numeric input;
- combobox;
- A-Book query input;
- поля критериев оценки.

## Базовое состояние

- фон: белый / системный surface;
- border: нейтральный системный;
- text: основной текст;
- placeholder: muted secondary;
- высота обычного input: 48px;
- textarea — с корректной высотой и resize по правилам UI;
- border-radius как в Core DS;
- padding внутри поля системный;
- без лишних теней;
- без грязного серого фона у активных редактируемых полей.

## Hover

- border чуть контрастнее;
- без резкой смены фона;
- без декоративных теней.

## Focus

- явный focus ring / focus border;
- цвет focus только системный;
- не использовать случайный синий или чёрный outline.

## Error

- error border;
- helper text под конкретным полем;
- не красить весь блок, если ошибка относится к одному полю.

## Disabled

- muted background;
- muted text;
- cursor not-allowed;
- tooltip или helper text, почему действие недоступно.

# ЭКРАН “ВОПРОС” — ОТДЕЛЬНО ИСПРАВИТЬ

Форма вопроса должна выглядеть как Core DS form, а не как набор кастомных полей.

## Поля

- “Название вопроса” — обычный input.
- “Текст вопроса” — textarea.
- “Рубрика A-Book” — select / dropdown.
- “Запросы к A-Book” — input / chips input.
- “Критерии оценки” — системная form-card.

## Критерии оценки

Сейчас блок критериев выглядит тяжеловато.

Нужно сделать так:

Карточка:
- заголовок: “Критерии оценки”
- справа статус: “100 / 100 баллов”

Если сумма = 100:
- status success.

Если сумма ≠ 100:
- status warning:
  “Сумма баллов должна быть 100”

Строка критерия:
- grid layout:
  - текст критерия;
  - баллы;
  - удалить.

Пример:

[Точность фактов                ] [40] [delete]
[Структура ответа               ] [30] [delete]
[Эмпатия                        ] [30] [delete]

Правила:
- поле баллов компактное;
- delete icon внутри зоны 32×32;
- delete icon не должен быть визуально главнее контента;
- не использовать лишние красные иконки в заголовке;
- если критерий последний — delete disabled.

# ВЕРХНИЙ STEPPER

Сейчас stepper перегружен и выглядит не по банковской дизайн-системе.

Пересобрать stepper.

## Требования

Stepper должен быть:
- строгий;
- чистый;
- системный;
- без лишних декоративных иконок;
- похожий на enterprise Core DS UI, а не на consumer app.

## Для каждого шага показывать только:

- номер шага;
- название;
- состояние.

## Шаги тренажёра

1. Онбординг
2. Теория
3. Практика
4. Завершение

## Шаги экзамена

1. Онбординг
2. Практика
3. Завершение

## Состояния

Не начат:
- серый круг с номером;
- muted text.

Активный:
- красный акцент;
- stronger text;
- мягкий светло-красный фон pill/chip.

Завершён:
- минимальная status-индикация;
- можно использовать маленькую системную галочку, но не перегружать шаг.

Ошибка:
- error status;
- небольшая красная точка или error border.

## Запрещено

- не ставить рядом одновременно номер, большую иконку и дополнительную галочку;
- не использовать декоративные иконки около названий шагов;
- не делать stepper “игровым”;
- не перегружать красным цветом.

# НИЖНИЙ FOOTER BUILDER

Сейчас footer неправильный:
- кнопка “Отмена” внизу не нужна;
- “Готово к публикации” стоит не на месте;
- действия визуально конкурируют;
- footer выглядит случайно.

## Новая спецификация footer

В Builder footer НЕ использовать кнопку “Отмена”.

Footer должен быть sticky и содержать только сценарные действия.

## Структура

Слева:
- “Назад”

Справа:
- “Сохранить черновик”
- “Далее”

## На последнем шаге

Справа:
- “Сохранить черновик”
- “Проверить обучение”

## После успешной проверки

Справа:
- “Сохранить черновик”
- “Опубликовать”

## Если есть ошибки

Справа:
- “Сохранить черновик”
- “Исправить ошибки”

## Убрать из footer

- “Отмена”
- “Готово к публикации”
- статусный текст между кнопками
- лишние иконки
- зелёные статусы между CTA

## Где показывать статус готовности

Статус “Можно публиковать” / “Есть ошибки” / “Осталось заполнить 2 пункта” должен жить:
- в header;
- в правой панели;
- в validation drawer;
- в toast.

Но не в action bar между кнопками.

# HEADER BUILDER

Header должен быть стабильным и системным.

Слева:
- “← Каталог”
- название обучения
- статус

По центру или рядом с названием:
- статус автосохранения:
  - “Сохранено”
  - “Сохраняем…”
  - “Есть несохранённые изменения”

Справа:
- “Проверить”
- “Предпросмотр”
- “Сохранить”
- “Опубликовать”

Правила:
- primary CTA только один;
- “Опубликовать” — primary только когда обучение готово;
- “Сохранить” / “Сохранить черновик” — secondary;
- “Проверить” и “Предпросмотр” — tertiary;
- не использовать несколько красных кнопок на одном уровне.

# ПРАВАЯ ПАНЕЛЬ

Правая панель должна быть структурной, а не “свалкой”.

Порядок блоков:

1. Готовность
2. AI-подсказки
3. Проблемы в этом блоке

5. Контекстные настройки

## Блок “Готовность”

Показывать сверху правой панели.

Состав:
- заголовок: “Готовность”
- процент, например “84%”
- progress bar
- короткий статус:
  - “Можно публиковать”
  - “Осталось заполнить 2 пункта”
  - “Есть ошибки в структуре”

Ниже мини-чеклист:
- Онбординг — готово
- Теория — готово

## AI-подсказки

Показывать компактно.

Если подсказок нет:
- не показывать большую пустую карточку;
- показать компактный текст:
  “Для этого блока нет подсказок”

## Проблемы в этом блоке

Если ошибок нет:
- компактный статус:
  “Этот блок без ошибок”

Если есть ошибки:
- список ошибок;
- ошибки кликабельные;
- клик ведёт к нужному полю.

Таблица:

# ВИЗУАЛЬНЫЙ СТИЛЬ

Стиль:
- банковский enterprise UI;
- светлая тема;
- чистые формы;
- строгая типографика;
- минимум визуального шума;
- красный только для primary CTA, ошибок и важных статусов;
- без consumer-app декоративности;
- без случайных иконок;
- без “игрового” интерфейса.

Design tokens ориентировочно:
- Background: #F3F5F8
- Surface: #FFFFFF
- Surface muted: #F8FAFC
- Border: #E5E7EB
- Text primary: #111827
- Text secondary: #667085
- Text muted: #98A2B3
- Brand red: #C62828 / #D32F2F
- Success: #12B76A
- Warning: #F79009
- Error: #D92D20

Если Core DS даёт свои токены — использовать Core DS токены вместо этих.

---

# ОТСТУПЫ

Использовать единую spacing system:

- 8px — базовая единица
- 12px — малые внутренние расстояния
- 16px — padding внутри карточек
- 24px — расстояние между карточками
- 32px — расстояние между крупными секциями
- 40px — максимум между связанными большими блоками

Запрещено:
- случайные большие пустоты;
- разные высоты одинаковых карточек;
- элементы, прижатые к краям;
- горизонтальный scroll;
- пустые карточки без действия;
- одиночные иконки в пустом пространстве.

---

# ИКОНКИ

Правила:
- основные иконки 16–18px;
- декоративные иконки 32–40px;
- иконка всегда внутри контейнера 32×32 / 40×40 / 56×56;
- не использовать красные иконки без причины;
- не использовать иконки как украшение там, где достаточно текста;
- иконки не должны обрезаться;
- иконки должны быть выровнены по вертикали с текстом.

---

# КНОПКИ

Все кнопки должны иметь состояния:
- default;
- hover;
- active;
- disabled;
- loading.

Disabled:
- визуально светлее;
- cursor not-allowed;
- helper text или tooltip с причиной.

Loading:
- spinner 16px;
- тексты:
  - “Сохраняем…”
  - “Проверяем…”
  - “Публикуем…”

---

# EMPTY STATES

Добавить empty states:

- пустой каталог;
- нет данных в аналитике;
- нет пользователей в доступах;
- A-Book ничего не нашёл;
- обложка не загружена;
- нет AI-подсказок;
- нет ошибок в блоке.

Каждый empty state должен отвечать:
- что произошло;
- что сделать дальше.

Весь UI на русском языке.

Тон:
- спокойный;
- ясный;
- полезный;

- “Сумма баллов должна быть 100”
- “Введите ответ, чтобы отправить его на проверку”

# EDGE CASES

Обязательно реализовать:

1. Пустой каталог.
2. Нет данных в аналитике.
3. Нет пользователей в доступах.
4. Ошибки валидации.
5. Публикация заблокирована.
6. Несохранённые изменения.
7. Автосохранение.
8. Не выбрана рубрика A-Book.
9. A-Book загружается.
10. A-Book ничего не нашёл.
11. A-Book результат утверждён.
12. Ошибка загрузки обложки больше 10 МБ.
13. Направление сбрасывается после смены фабрики.
14. Достигнут максимум:
    - 2 элемента онбординга;
    - 3 теории;
    - 3 критерия;
    - 3 подсказки;
    - 5 запросов A-Book.
15. Попытка удалить защищённый блок.
16. Удаление элемента с дочерними элементами.
17. Дублирование элемента с “(копия)”.
18. Редактирование опубликованного обучения переводит статус в “Есть изменения”.
19. Попытка выйти из конструктора с несохранёнными изменениями.
20. Ctrl+S сохраняет и показывает toast.
21. Пустой ответ в learner flow.
22. Отсутствующая обложка.
23. Таблица доступов с большим количеством пользователей.
24. Ширина экрана 1440px.
25. Ширина экрана 1920px.
26. Сумма критериев оценки меньше или больше 100.
27. Disabled кнопка должна объяснять, почему действие недоступно.
28. Footer builder не должен содержать “Отмена”.
29. Stepper не должен содержать лишние иконки.
30. Инпуты не должны иметь случайные цвета и стили вне Core DS.
