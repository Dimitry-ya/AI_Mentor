# ОБЯЗАТЕЛЬНОЕ ТРЕБОВАНИЕ: UI ДОЛЖЕН СООТВЕТСТВОВАТЬ CORE DS

Перед доработкой интерфейса обязательно изучи и используй дизайн-систему банка:

- Core DS GitHub:
https://github.com/core-ds/core-components.git

- Core DS Docs:
https://core-ds.github.io/core-components/master/?path=/docs/intro--docs

- Пример компонента CheckboxGroup:
https://core-ds.github.io/core-components/master/?path=/docs/checkboxgroup--docs

UI AI-Ментор должен визуально и поведенчески соответствовать Core DS.

Если возможно — подключи компоненты из `core-components`.
Если прямое подключение невозможно — воспроизведи визуальный язык Core DS вручную через текущие компоненты проекта.

Нельзя стилизовать интерфейс “на глаз”.
Все базовые элементы должны быть приведены к Core DS-like стилю:

- Button
- Input
- Textarea
- Select
- Dropdown
- Checkbox
- Radio
- Tabs
- Table
- Modal
- Tooltip
- Badge / Status
- Stepper
- Form layout
- Validation states

# ОБЯЗАТЕЛЬНАЯ ПРАВКА: УПРОСТИТЬ STEPPER

Упростить stepper в верхней части builder.

Сейчас stepper перегружен: дополнительная зелёная check-иконка внутри активного шага визуально лишняя и не соответствует строгому enterprise UI.

## Что нужно сделать

Убрать дополнительную иконку статуса внутри активного шага.

Не использовать отдельные зелёные check-иконки внутри stepper.

Оставить только:

- номер шага;
- название шага;
- активное состояние;
- при необходимости тонкий разделитель между шагами.

## Как должно быть

Stepper должен выглядеть так:

1 Онбординг  
2 Теория  
3 Практика  
4 Завершение

Без лишней иконки справа от названия шага.

## Состояния stepper

### Неактивный шаг

- серый номер;
- спокойный muted text;
- без иконок.

### Активный шаг

- красный акцент;
- более заметный текст;
- мягкий светло-красный фон, если нужен pill/chip;
- без зелёной check-иконки.

### Завершённый шаг

- показывать статус не отдельной иконкой внутри stepper, а через:
  - цвет шага;
  - состояние текста;
  - общий статус блока в правой панели;
  - общий статус готовности.

### Ошибка

- допускается минимальная error-индикация;
- не перегружать шаг иконками;
- ошибка должна быть также видна в дереве, right panel и validation drawer.

## Запрещено

- не использовать зелёные check-иконки внутри stepper;
- не ставить иконку справа от названия активного шага;
- не использовать декоративные иконки в названиях шагов;
- не делать stepper похожим на игровой / consumer UI;
- не перегружать stepper красным, зелёным и иконками одновременно.

## Цель

Stepper должен выглядеть:

- чище;
- компактнее;
- спокойнее;
- ближе к enterprise UI банка;
- визуально совместимым с Core DS.

# ОБЯЗАТЕЛЬНАЯ ПРОВЕРКА ПОСЛЕ ДОРАБОТКИ

После реализации обязательно проверить:

1. Stepper не содержит зелёную check-иконку внутри активного шага.
2. Stepper состоит только из номера, названия и состояния.
3. Активный шаг считывается без дополнительной иконки.
4. Завершённость шага не показывается лишней иконкой внутри stepper.
5. Статус готовности показывается в правой панели / header / validation summary.
6. Визуальный стиль stepper соответствует Core DS-like enterprise UI.
7. Все базовые компоненты интерфейса соответствуют визуальному языку Core DS.
8. Нет кастомных случайных цветов, теней, focus states и border-radius вне дизайн-системы.
